Four ways to knock a Siemens edge gateway off the PROFINET segment — and blind SCADA while you do it

Nozomi Networks Labs published research on 15 September detailing four memory-corruption flaws in the PROFINET Discovery and basic Configuration Protocol implementation on the Siemens SCALANCE LPE9403 industrial PC, found using emulation-driven snapshot fuzzing with the Unicorn CPU emulator and AFL++. The flaws are tracked as CVE-2025-40575 through CVE-2025-40578 — an uninitialised-value issue, a NULL pointer dereference and two out-of-bounds reads — each carrying a CVSS 4.0 score of 5.3, and affect firmware up to V4.0 HF0. The DCP daemon runs as root, requires no authentication and is bound to all three device interfaces, so an attacker already on the same Layer 2 segment can crash it with crafted Ethernet frames. Siemens has shipped fixed firmware.

No exploitation reported — this is coordinated vendor-fixed research, not observed attack activity. The impact is availability rather than code execution: crashing the DCP service makes the device appear unreachable to discovery, which Nozomi notes can effectively blind SCADA systems that rely on it, and during initial commissioning can prevent the device obtaining an IP address at all. The attack requires adjacent-network access to the same Layer 2 segment, which is why the modest 5.3 score understates the operational nuisance in a flat plant network and overstates it in a properly segmented one. Confirmed vs claimed: the vulnerabilities and the fix are confirmed by Siemens in security report SSA-327438; the operational impact described is Nozomi’s assessment, and no in-the-wild exploitation is known Not in CISA KEV — no exploitation reported

Make sure your alarm handling distinguishes “device stopped answering discovery” from “device is fine and the daemon died.”
